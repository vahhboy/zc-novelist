## 推送故障的新解法（2026-10-12 更新，替代旧结论）

- 本次 `git push` 连续两次超时（第一次被默认超时中断、`timeout 100` 返回 124），**不是 502**，是会话注入的 http 代理 `127.0.0.1:61931` 不通（env 里的 `http_proxy/https_proxy/HTTP_PROXY/HTTPS_PROXY` 都是这个端口）。
- **解法：绕过代理直连，一次成功**：
  ```bash
  env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY git push
  ```
- 顺序定为本仓库的固定打法：**默认代理 →（超时）→ 绕代理直连 →（仍不行）才交给作者手动 push**。不改 remote、不换 SSH 这条红线不变。
