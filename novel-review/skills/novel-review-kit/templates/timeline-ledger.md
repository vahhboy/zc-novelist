> 台账版本：vX.X · 最后更新：YYYY-MM-DD · 累计覆盖至：第 X 章
> 维护席位：钟不紊（`novel-logic-auditor`）｜每轮 Workflow A / B / F 后由主理人追加更新
> 评分量表版本不适用本台账

---

## 为什么要有这份台账

**它是相对时间不再失效的前提。** 没有台账，每一轮审校都要从零重算全书时间账——历史上钟不紊一席曾为此把同一部 4759 行正文反复通读 12 次。

有了台账，每次只需：读台账尾部 → 校验本次覆盖范围 → 追加新行。

---

## 使用规则

1. **只追加，不重写**：每次审校只追加本次覆盖范围的行，原有行原样保留
2. **修订保留原值**：发现旧行错了，**不要直接覆盖**——在「备注」写明修订原因并保留旧值。旧值是回溯"当初为什么这么定"的唯一凭据
3. **推算必须留痕**：跨度过长、正文无明写的段落，必须在「备注」写明推算依据（如"按第 8 章『三日后』推定"）
4. **冲突不删除**：曾经报错、后来确认非问题的条目，移入下方「已了结」表并保留结论，避免下一轮重复劳动

| | | | | | | | |

**字段说明**

| 字段 | 填写规则 |
|---|---|
| 章 | 章节编号，跨章连场时写起止（如"第 12–13 章"） |
| 场次 | 该章内的段落标识，便于回查（开场 / 中段 / 收尾 / 或以小标题标识） |
| 绝对时刻 | 正文有明写则照录原文措辞；无明写留空，靠「相对锚点」定位 |
| 相对锚点 | 相对上一个已知时刻的表述，原文照抄（"三日后""次日午时"） |
| 本段跨度 | 本场次内部消耗的时间（如"三天""一个时辰"） |
| 全书累计 | 从第 1 章起算的累计天数/时刻，是冲突判定的主要依据 |
| 在场人物 | 用于验证在场性与行程可行性（同一人不能同时出现在两地） |
| 备注 | 推算依据、修订记录、存疑标记 |
